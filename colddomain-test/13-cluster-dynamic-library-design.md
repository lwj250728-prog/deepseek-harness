# 13 · 簇作为动态经验库：多归属 + 降级梯子设计

> 状态：设计草案（未实施）。来源：2026-08-31 起的数据驱动管线改进讨论，本轮收敛于簇机制的多归属与无命中语义。
> 前置文档：07-handoff-context.md（总交接）、08-12-*.md（各轮报告）。
> 原则遵循：exp_125 教训——先数据验证后实施；诚实评估影响。

## 1. 背景与动机

### 1.1 纯嵌入检索 = 静态数据库（用户论点，已确认）

嵌入是固定函数 `f(text) → vector`，余弦是固定算子，二者都不随经验库变化。全库逐条检索在固定索引上线性打分——经验增长只改变行数，不改变结构。动态性只能来自组织层（谁和谁归一类、哪类分裂/合并/新生/成熟结晶），簇就是这层状态。

### 1.2 簇不能高成本运行（用户论点，已回应）

簇是有状态机制，hash/嵌入是无状态算子。拆成两笔账：

- **在线（查询路径）**：簇导航 = 1 次 embed API（同一查询向量复用）+ k 次质心余弦 + |命中簇| 次簇内余弦。当前数据 k=3、N=326：3 + 32 ≈ 35 vs 326，约 9 倍缩减，API 成本一分不多。查询只读已提交的簇表快照，不触发任何演化逻辑。
- **离线（维护路径）**：增量归属 O(k) 本地余弦（与嵌入回填同批）；定期重组复用冷循环 `rebuildTaxonomy` cadence（agglomerative 确定性本地运算，触发式、低频、不阻塞查询）；质心迁移零新 API 调用（326 条 100% 已存 `exp.embedding`，质心 = 成员嵌入平均）；LLM 只在成熟簇规则蒸馏（可选、触发式）。

结论：强制性路径全部是"存好的向量上做本地数学"，LLM 逐出必经路径——簇机制可以与嵌入检测同量级低成本运行。真实成本是状态维护的实现复杂度（谱系账本、分裂信号、重组触发），而非算力。

### 1.3 诚实的边界

N=326 时，簇导航的 9 倍在线优势在 CPU 上是噪声（微秒级）。簇的真实价值是**结构**（判别、成熟、谱系、蒸馏入口），真实成本是**维护复杂度**。簇的收益随 N 增长：10 万条时全库线性扫描才是真贵，索引是刚需。

## 2. 已确认的设计原则

1. **簇 = 组织层（动态演化归属），嵌入 = 相似度算子（静态函数），链 = 规则提取层。** 簇做演化、不做内容加工；加工归链。簇的 `decisionRule` 遗留（`cold-engine.ts` line 574 硬编码模板）应退役。
2. **簇机制可以低成本运行**：强制性路径全是本地向量数学，LLM 仅出现在可选蒸馏步。
3. **实例经验可以多归属**：一条经验可同时属于多个维度、多个簇（软归属带权重）。
4. **无命中 = 演化信号**（用户已确认）：簇导航 0 命中 → 新生簇候选池；簇内过滤空 → 覆盖缺口记录；低于阈值 → 阈值校准统计。降级梯子与冷循环闭环。
5. **LLM 定轴、embedding 聚类**（用户确认）：LLM 负责**确定判别维度与判别词**（轴，如"新手↔资深"是同一任务的两个用户画像轴），embedding 负责**在确定的轴上做确定性向量聚类**（表示 + 分组）。聚类永远确定性本地（可复现、簇 id 稳定、谱系账本不乱）；LLM 只在轴发现/命名/判别词层面介入——这正是现有 `reconstructTaxonomy` 因果锚定步的职责，只是把输入从效用分组换成语义分组。

### 2.1 "轴从哪来"（LLM 定轴的输入）

轴不是 LLM 凭空想，而是从**语义簇的组间差异**中提炼：embedding 聚类给出确定性分组后，LLM 对比组间成员文本，识别"同一任务、不同用户画像"这类判别轴并产出判别词。这是离线低频步，复用现有 LLM 路由（exp_23 已验证 LLM 路由让效用评分产生区分度），不进入在线路径。

## 3. 多归属归属表（数据模型）

当前 `clusters.json` 的 `supportingEvidenceIds` 是硬集合（agglomerative 硬聚类，每条经验被迫选边站）——exp_56/57 病根之一：新手经验被资深簇质心吸走，判别词被揉平。

新模型：**归属表** `(expId, clusterId, dimension, weight)`，一条经验多行、带软权重。隐喻：图书馆一本书可同时在多个书架有索引条目。

- **维度**（`dimension`）：簇按组织维度分层。候选维度：`situation`（情境）/ `action`（动作）/ `outcome`（结果）。现有经验已存 `situationVector`/`actionVector`/`outcomeVector`（hash 空间）与 `embedding`（语义空间），投影不是新成本。
- **软权重**（`weight`）：非二元 in/out，如嵌入相似度/置信度。属性过滤从"必须匹配"改"加权"（不匹配只降权不剔除）——属性缺失不阻塞召回。
- **谱系账本带维度**：分裂/合并按维度各自演化，lineage 加 `dimension` 字段，重组原因入账（复用 chain/trace 账本模式）。

### 3.1 已确认的代价

- 归属膨胀：326 条 × 2 维度 × 每维 1-2 簇 ≈ 千行级，账本写放大一个量级（可控）。
- 冷循环多维度：每维度跑一次聚类（D 次），3 维度即 3x——冷循环本就低频，可接受。
- 跨簇去重：同一经验可能从多个簇召回——现有 `coolDownInjected` 已按 expId 去重，天然免疫；topK 合并时按相似度再排一次。

## 4. 簇生命周期（动态经验库机制）

簇生命周期由两个**性质不同**的操作构成，必须分开设计（用户指出的关键区分）。

### 4.0 现状差距

当前实现只有一条路径：`rebuildTaxonomy` 冷循环全量重建（`cold-engine.ts`：agglomerative 整批产出候选簇 → 新旧全量 sandbox backtest → 整体写回）。"新增"被揉在重建里——新经验要等下次全量重建才并入簇集合（动态性延迟），且重建扰动所有簇（为加一个节点付出全局代价）。簇新增（birth）与簇重建（rebuild）必须拆成两条独立路径。

**关键现状事实：当前簇在"结果效用空间"聚类，不在语义空间。** `clusterVectorOf`（line 109）用的是 `outcomeVector`（结果向量），agglomerative 在效用空间按质心余弦合并（line 138）。**验证实测（`colddomain-test/cluster-space-probe.mjs`，2026 会话）：新手簇(8) vs 资深簇(9) 两组证据在效用空间组间质心余弦 0.9168（距离 0.0832），组内 0.78/0.83——组间距离只有组内距离的 0.42x，完全不可分；同一判别维度在 bge-m3 语义空间组间余弦 0.7917（距离 0.2083，2.5 倍于效用空间），可分性 0.56x——显著改善但仍重叠。** 结论：判别维度（新手/资深）在效用空间不存在（结果都是成功 5-8）；语义空间能捕获但未完全分离。修复不是"换聚类算法"，而是**换聚类空间** + LLM 判别维度补充。**多归属的维度设计因此是"在现有结果维之上新增情境维/动作维"**，且各维用各自最合适的空间（语义维用 embedding、结果维沿用效用向量）。

**全簇验证实测（`colddomain-test/cluster-validation.mjs`，327 条全量）：**
- **覆盖危机：簇成员经验仅 12/327（3.7%），孤儿 315 条（96.3%）。** 簇从未真正组织过经验库，只是 3 个标签壳——这解释了为何注入一直靠全库嵌入扫描（覆盖 100%）。C 形态实施必须**先全量重聚类建立基线**（327 条全入簇），再定轴。
- **换空间证据成立：** 效用空间簇间质心平均相似度 0.8219（2 对 ≥0.85 重叠：8↔9=0.9168、8↔10=0.8548）；语义空间 0.7084（0 对超标，8↔9=0.7917 仍为最近对——正是 LLM 定轴的判别难点，与 exp_56/57 对上）。
- **簇纯度：** 语义簇内中位距 0.32-0.47 vs 效用 0.19-0.26——语义簇更分散是因为保留更多判别维度信息，非缺陷。

### 4.1 簇新增（birth，增量路径）

- 触发：孤儿经验池积累 ≥ evidenceMinCount（例如 3）。池子统一收两类信号：
  - 离线：入库时增量归属无法归属任何簇（最大质心相似度 < t_new，如 0.45）
  - 在线：查询无命中（降级梯子 ①）记入候选池
- 动作：从池子经验创建一个新簇，质心 = 成员嵌入平均，写归属表 + 谱系账本（parentIds 空，origin: 'birth'）
- 成本：O(孤儿数 × k) 质心比较 + 一次质心计算，纯本地
- 扰动：**零**——只加节点，不动任何现有簇
- 时机：即时（每批入库后检查），不必等冷循环——新领域经验很快形成新簇，动态性即时可见

### 4.2 簇重建（rebuild，批量路径）

**触发（新设计，取代现状单一"误差≥0.8"信号）：** 结构信号 + 误差信号双通道，且与 4.1/4.3 生命周期分层对齐：

| 触发层 | 信号 | 动作 | 回答的问题 |
|---|---|---|---|
| 即时（每经验） | 增量归属 | 滑动更新质心（4.3） | 归到哪？ |
| 事件驱动（每 N 个孤儿） | 孤儿池 ≥ evidenceMinCount（4.1） | **簇新增**（只加节点） | 是不是新领域？ |
| 结构信号（低频） | 见下 | **簇重建**（分裂/合并/重定轴） | 组织结构还对不对？ |

**簇重建的具体触发信号：**

1. **簇内不纯度超标**：某簇成员在语义空间两两相似度方差显著上升，或出现 ≥2 个稳定子群 → 该簇该**分裂**（exp_56/57 正是此场景：新手/资深被揉成一簇，不纯度早已超标）。
2. **簇间质心重叠**：两簇质心余弦 > 阈值（如 0.85）且跨簇最近邻比例高 → 该**合并**。
3. **轴判别失效**：LLM 提炼的判别词在查询侧路由中的判别准确率跌破阈值（如 < 0.6，用现有 predictionError 数据统计）→ 该**重定轴**（重新跑 LLM 轴提炼）。
4. **误差信号（保留现状兜底）**：预测误差 ≥ emergencyErrorThreshold → 紧急 local 修补。
5. **新增无法成簇**：孤儿池长期积累但 evidence 校验总失败 → 现有轴体系覆盖不了 → 触发**全局重定轴**。

**关键点：触发 ≠ 执行。** 触发只产生候选，执行前仍过现有 sandbox backtest（15% 门槛或冷启动不劣化）——结构信号不会造成扰动风暴，每次重建前都有验证门槛。

**scope 自动选择**：信号来自哪个簇 → `local`（只修那簇）；多簇同时超标或轴失效 → `global`。scope 由信号决定，不再靠人手动传参。

**与无命中演化闭环**：结构信号的数据源是 §5 降级梯子记账的产出（覆盖缺口、频繁兜底、阈值漂移）——重建触发不是孤立误差事件，而是检索系统自身反馈的累积。

**诚实评估**：新方案下重建**更频繁被触发**（结构信号比"误差≥0.8"敏感），但**每次更便宜**（local 优先、backtest 把关）——净效果是"小步快修"而非"积重难返"。风险是信号阈值（不纯度、重叠、判别准确率）需数据标定，不能拍脑袋——见 §7 第 5 项。

- 动作：分裂（簇内 pairwise 相似度双峰 / ≥2 稳定子群）、合并（质心余弦 > 阈值且跨簇最近邻比例高）、重分配
- 成本：O(样本²) agglomerative，低频
- 扰动：高——簇集合可能整体变化，依赖谱系账本（带 dimension）追踪
- 定位：只做真正的"重组"，**不再承担"新增"职能**

### 4.3 增量演化通道（新增之外的轻量维护）

- 增量归属顺带**滑动更新命中簇质心**（O(1) 加权平均）——成员缓慢演化不触发重建
- 经验条目不直接引用簇 id，归属只在归属表——重组不需回写经验，冷却账本按 expId 不受影响

### 4.4 成熟簇 → 链蒸馏

簇跨重组稳定 + 成员足量 → 触发规则蒸馏，复用 distillChainPrinciple 机制、**不依赖 chainId**（解决 exp_185：91% 经验无 chainId 孤儿）。簇成为链接入点。

## 5. 检索降级梯子（精筛无命中的改进）

三种无命中情形：

| 情形 | 含义 |
|---|---|
| ① 簇导航 0 命中 | 查询与所有质心都远（OOD / 新领域） |
| ② 簇命中但簇内过滤空 | 属性过滤剔光了（该簇缺该属性经验） |
| ③ 有命中但低于阈值 | 弱关联情境 |

降级梯子（从窄到宽，每级放宽一个条件）：

```
L0 严格：簇导航(top-1 簇, 质心≥t1) → 簇内嵌入排序 + 属性过滤 → topK
L1 放宽属性：过滤从"必须匹配"改"加权"（③ 的主要兜底）
L2 扩展簇：命中簇 → lineage 兄弟/母簇，或多归属跨维度簇（② 的主要兜底）
L3 退全库：簇导航失败/簇内全空 → 退回现状全库嵌入扫描（① 的主要兜底）
L4 触发门降阈：现有显著性门失败降阈 + 词命中加成（triggerBoost 0.15）
L5 OOD 试探：仍无 → predictNovel scratchpad 试略（已有机制，F2 已修复）
```

关键保证：**L3 兜底 = 现状全库扫描，簇机制上线后检索不会比现在更差，只会更好或持平。**

无命中即演化（已确认原则落地）：

- ① → 查询进入**孤儿经验池**（与入库无法归属统一为同一池子，积累 ≥ evidenceMinCount → **即时簇新增**，见 4.1，不等冷循环）。OOD 不是错误，是簇演化原料。
- ② → 记录该簇**覆盖缺口**（缺什么属性、缺多少）→ 增密信号：下次同属性经验优先归属该簇。
- ③ → 记入阈值校准统计：某级频繁兜底（如 L1 兜底率 > 60%）→ 上一级条件太严，属性过滤条件/质心阈值该放宽。

每次降级路径记账（复用 trace.jsonl 模式），统计各级兜底率——这是一条可学习环路：哪级兜得多，就调哪级的上一级条件。这是"动态"区别于"静态嵌入库"的行为：嵌入检索无法从"没检索到"里学到任何东西，簇可以。

## 6. 开放决策点（待用户拍板）

**已决：**
- **在线形态 = C**（用户确认 2026-09-XX）：簇离线演化 → 判别权重表参数化在线扫描。在线成本与嵌入检测完全一致（1 API + N 余弦 + 词加成），零在线变更；判别权重表是簇演化的产物，随簇新增/重建自动更新。实现路径：把 `cognitive-inject` 现有的 `symptomOverlap` + `triggerBoost` 词加成从静态词表升级为簇离线产出的判别权重表。A（cluster-then-search 在线索引）保留为规模上来的终态。
- **维度数 D = 2**（用户确认 2026-09-XX）：情境 + 动作。新手↔资深是情境维内判别（用户熟练度属场景），先讲解↔直接执行是动作维内判别；两轴各归其位，判别权重表按维分开，查询侧加成互不干扰。

### 6.1 C 形态实施路径（三步）

```
第1步 语义全量重聚类（确定性本地 agglomerative on embedding，零 LLM）
      327 条全入簇（解决覆盖危机：孤儿 315 → 全量基线）；结果维保留现有效用簇
第2步 LLM 定轴（离线低频）：从新簇组的组间差异提炼判别轴/判别词（情境维+动作维）
      复用 reconstructTaxonomy 因果锚定步，输入从效用分组换成语义分组
第3步 产出判别权重表 {dimension, axis, term, weight} → 注入在线扫描
      cognitive-inject 的 symptomOverlap/triggerBoost 从静态词表改读权重表
```

实施顺序由验证数据钉死：**先解决覆盖（第1步），再定轴（第2步），最后接在线（第3步）**——判别权重表若只从现有 3 簇提炼，覆盖 3.7%，无意义。
