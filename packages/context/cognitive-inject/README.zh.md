# @deepseek-ai/dsh-cognitive-inject

[English](README.md) | 中文

面向认知流水线的**步骤级 SAR 经验预热**。在每个 agent 的每一步开始前，从即将进入模型请求的消息中提取当前情境，**只有当情境携带触发信号**（上一步失败、求助/探索/决策类行为词、或从重要存储经验中派生的关键词）才检索情境相关经验并把最近命中作为参考上下文注入。上一步失败时唤起更激进——这是"记忆连锁唤起"的对应物：失败是最强的情境线索，因此上一次的挫败会把相关历史经验浮现出来，供重试步骤更快匹配。

## 插件做什么

```
主对话 / 子任务 每步开始前
  → agent/pre-step → 提取当前情境文本（最近 N 条消息块）
  → 触发门：上一步失败？或 消息含触发词？（静态行为词 / SAR 派生关键词）
  → 触发才检索经验库（行动轴 ∪ 情境轴，取 max；失败标记重叠按语义加成）
  → 否决门：模板7精排判定 top 候选是否真正适用（LLM 路由存在时）
  → 通过 → 注入【认知经验参考】块（source: cognitive-inject）
  → 上一步工具失败 → 阈值放宽 + 注入条数提升 + "上一步执行失败"标记
```

- **步骤级预热** — 与 orchestrator 的一次性子任务前注入不同，本插件在每个 agent 的每一步都召回，因此经验恰好在当前情境相似的那一刻浮现——包括任务执行中途、bug 首次出现时。
- **触发式注入** — 人类在失败、面对新任务、做高后果决策时才翻过往经验，不会在闲聊时打断自己翻历史。注入同样受触发门控制：上一步失败总是触发；否则进入步骤的消息必须携带触发词。**静态行为触发词**（失败/报错/卡住/排查/怎么/如何/试试/风险/以前/遇到过/发布/部署/计划…）按子串匹配；**SAR 派生触发词**来自重要存储经验——高效用、高危、或高频命中的经验，其情境/行动 token 按重要性（|效用分|/15 + 高危 + 高频）累加为逐词权重，取 top-60 归一化，触发权重和 ≥ 0.6 即触发。像"重启一下"（常规）即使检索能命中字面弱相关也绝不注入；"帮我排查测试挂起"（求助）与"打包插件到GitHub"（命中失败推送经验的派生词）都会触发。
- **双轴检索 + 症状加成** — 情境文本同时匹配经验的行动向量与情境向量，取较高者。像"测试突然挂起"这样的任务文本，能召回*情境*为"测试突然挂起"的 bug 经验，即使修复措辞完全不同。失败症状重叠（查询与经验文本都含 挂起/超时/编译失败…）在语义分之上加一个**与语义分成正比**的封顶加成（`SYMPTOM_BONUS = 0.3`）——它让当前挫败的召回更锐利，但字面标记重合永远不会把毫不相关的经验拖过阈值（实测：语义 0.11 + 标记 1.0 在固定加成下得 0.41 被注入；按比例加成后降为 0.14、低于 0.4 门槛不再注入，而真正相关的 0.47 情境分保持 0.61）。
- **否决门（LLM 精排兜底）** — 过阈值的候选不自动注入：当流水线配置了 LLM 路由时，模板7"检索精排官"阅读情境与候选全文，判定其是否**真正适用**（字面命中 ≠ 可迁移）。每次否决换下一个候选（有界，`INJECT_VETO_MAX = 2`；注入块注明否决条数），全部否决则完全不注入。无路由时降级为仅阈值行为。默认 `topK: 1` 时否决要么放行唯一候选、要么抑制注入——需要否决后落到次优候选请把 `topK` 设为 ≥ 2。
- **失败强启动** — 当某 agent 最近一次工具结果为错误时，相似度阈值乘以 `failureThresholdFactor`，最多注入 `failureTopK` 条经验，并加"上一步执行失败"前缀。
- **模型可见 ⟺ 已记录** — 参考块随步骤的 `decision.messages` 进入请求，由 agent loop 作为持久的 `user/message` 事件落盘；回放与分发看到的与模型所见完全一致。

## 快速开始

在认知流水线旁装配本插件：

```yaml
- id: cognitive-inject
  name: '@deepseek-ai/dsh-cognitive-inject'
  config:
    topK: 1
    minSimilarity: 0.4
```

`web` profile 已在认知流水线之后挂载（见其 `cordis.patch.yml`）；其他 profile 可在 patch 或 bundle 中加入以启用步骤级预热。

## 配置

全部字段可选；默认值偏保守以避免上下文噪声。

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `topK` | `1` | 最多注入多少条相关经验 |
| `minSimilarity` | `0.4` | 判定记忆相关的最小情境相似度 |
| `failureThresholdFactor` | `0.6` | 失败步骤后 `minSimilarity` 的乘法因子 |
| `failureTopK` | `3` | 失败步骤后最多注入多少条经验 |
| `contextDepth` | `4` | 参与情境提取的尾部消息块数量 |
| `enabled` | `true` | 为 false 时保留监听但不注入 |

## Model Experience

### 注入的参考块

#### What the model sees

在符合条件的步骤，模型会收到一条额外的 `user/message` 参考块：

```
【认知经验参考】以下是与当前情境相关的历史经验，供参考借鉴（不要虚构为当前事实）：
- [exp_8] (相关度 0.52) 深夜出现了一个会死循环的浮点 bug。紧急修复了该浮点 bug。测试全部恢复…
```

块归属 `cognitive-inject` source，仅在命中超过阈值时注入，因此大多数步骤不产生额外 token。

#### Token effect

条件性：未命中为零 token，命中时每块约 60–120 token。失败路径最多注入 `failureTopK` 块，但只在真实工具失败之后。

#### KV Cache effect

注入块是步骤局部的 `user/message`，不是 system-prompt 小节，不影响前缀复用。检索复用流水线同一套哈希词袋向量，存储与重建保持可复现。

## Known Limitations and Deferred Work

- **哈希向量情境匹配** — 情境文本用流水线的确定性词袋向量匹配，同义词不命中；真实嵌入 seam 是流水线的 deferred work，本插件继承之。
- **失败标记按 agent 而非按步** — 插件只记录每个 agent 最近一次工具结果；失败与下一次 pre-step 之间若隔了一个成功步骤，与立即重试不做区分。
- **无跨 agent 召回** — 预热读取共享存储，但经验只注入正在运行步骤的 agent；父对话要等下一步才会看到子任务刚写入的经验。
