# Agent Note: 数字生命 M4——侧栏生命条

Status: implemented

[English](2026-09-03-digital-life-m4-sidebar-life-strip.md) | 中文

## 问题

数字生命的基质（情景链、轨迹台账、经验）在 GUI 里不可见：侧栏把所有会话平铺成列表，没有标记主对话，当前状态只存在于工具才能读的文件里。"主对话即入口"的姿态需要一个可见面孔——一处能一眼读到生命当前状态与近期轨迹的地方，位于会话列表之上。

## 决策

新侧栏槽位 `sidebar.life` 位于浏览区之上（由 ui-sidebar 外壳声明，ui-cognition 注册 occupant）：一个可折叠的**生命条**，挂载时拉取只读 `life.overview` RPC 并渲染：

- 链头状态卡——情景文本、提交年龄、归属会话（截断），当归属者即指定会话时显示「主对话」徽标（v1 指定 = 拥有当前链头的会话）；
- 最近轨迹作为迷你时间线——类型词（注入/提交）、来源徽标（工具/自举/回合末/压缩）、节点 id、年龄；
- 侧栏折叠成 rail 时退化为一个生命图标触发器；刷新按钮重新拉取。只读、无轮询——与学习区同纪律。

`life.overview` RPC（host：apiproxy `life` 域；数据：`ctx.situationalState.head()`/`traceTail`）随其 wire schema、客户端方法、connection fixture 与 fake-api 覆盖一并加入；connection/runtime 的假客户端补上该方法，slot-catalog 针对新槽位重新生成。

## 验证

客户端套件全绿：ui-cognition 20/20（5 个新 LifeStrip 用例：挂载拉取 + 状态卡、带来源徽标的轨迹行、展开/收起、rail 触发器、空链提示）、ui-sidebar 25/25（新槽位快照已更新）、connection + runtime 受影响包共 494/494，客户端聚合类型检查干净。host `life.overview` 已对运行中的 web 服务活体探测（链头 sstate-10，指定会话 = 当前活跃对话）。

## 备选方案

- **复用 `sidebar.learning`**：把生命条挂进探索任务区。否决——学习区是任务队列；生命的状态/轨迹是另一种读，属于浏览区之上。
- **折进 workspaces 浏览器**：作为会话列表第一行固定渲染。推迟——会话浏览器是 ui-workspace 的领地；条置顶的放法让外壳改动最小，且对每个打开的会话数据读取一致。
- **先做宿主侧指定标记再发布**：发布前先持久化显式主会话 id。v1 否决——链头归属者已是"谁拥有当前状态"的活体事实；徽标如实展示，显式覆写可后续无 UI 改动地叠加。

## 后果

生命现在有了可见面孔：打开侧栏即可在会话列表上方看到主对话的当前状态与近期提交/召回，刷新更新，指定徽标让"主对话"可读。代价：多一个侧栏槽位与一个只读 RPC（无轮询、无突变动词）；生命条默认收起，展开前列布局不变。指定徽标只与 v1 规则（链头归属者）一样好；显式覆写与会话列表置顶仍是后续工作。
