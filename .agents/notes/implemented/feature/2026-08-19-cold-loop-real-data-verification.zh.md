# Agent Note：冷环真实数据验证——双区间验收、回退证据完整性、模板调用关闭思维链、前提分化涌现、检索咨询分类体系

[English](2026-08-19-cold-loop-real-data-verification.md) | 中文

部分取代：[2026-08-18-cold-loop-acceptance-first-build-and-deferral.md](2026-08-18-cold-loop-acceptance-first-build-and-deferral.md) —— 其决策 A 的首次构建门槛从 ≥15% 放宽为"不劣于基线"；baseRate 基线参照与暂缓（deferral）设计仍然有效。

## 问题

第一次用真实数据跑冷环（35 条经验、15 条采样、真实 `deepseek-official/deepseek-v4-flash` 路由）从未验收成功。合成测试（每族效用向量完全相同）掩盖了三个阻塞，前提分化实验与自指认知问题又暴露了第四个与第五个：

- **首次构建门槛不可达。** 验收要求相对空视图 baseRate 基线 `Δerr ≤ −15%`。2-3 条验证切片的任何可测量改善都被压在 15% 以下：2 条验证中仅 1 条命中簇时，测量上限只有 −6.98%。首次构建永远过不了门，store 永远停在 taxonomy 版本 0。
- **回退绕过证据校验。** 当所有模型簇都被驳回时，`finalCandidates = verified.length > 0 ? verified : fallbackCandidates(groupsWithUtility, byId)` 把**未经验证**的确定性分组重新引入——已被 pairwise 距离检查驳回的簇仍可能被写回。真实数据直接演示了它：聚合合并（余弦 0.4）把高代价离群点链式并入成功族，形成 pairwise 最大距离 0.960、超过 `evidenceMaxDistance`（0.85）的组；检查正确驳回，但回退路径把它复活了。
- **模板调用静默饥饿。** `deepseek-v4-flash` 默认开启思考。管线的结构化调用预算受限（`callJson` maxTokens 500-4096）；思维链吃光全部预算，产生 `finish: max-tokens` 且零文本。每次 reconstruct 调用都抛 `LLM_MAX_TOKENS`、降级到确定性回退，改进后的提示词根本没到达模型——LLM 路由（设计的上限）在没有任何错误浮出水面时就已经死掉了。
- **前提分化进不了分类体系。** 同一行动（例如打包推送到 GitHub）在不同前提（新手需教学 vs 资深求极简）下，基于结果效用的聚类与归属会把经验按结果并簇，与前提无关——情境从不反馈到聚类或归属，`situationCentroid` 被稀释成混合物，`matchSuccessReference` 无法按前提路由。
- **检索不咨询分类体系。** 即使分类体系已经存在，检索仍是盲扫：`retrieveTopK` 从不问"SAR 在这里有没有知识、落在哪个策略区"——覆盖缺口、路由置信度、前提误路由的风险对管道和模型都不可见。"SAR 能否知道 SAR 里有什么并给检索提建议"这个自指问题没有任何机制回答。

## 决策

**A —— 双区间验收。** `firstBuild = store.clustersSnapshot().length === 0`。冷启动接受首个验证过的簇集合当 `Δerr ≤ 0`（相对空视图 baseRate 基线，绝不被测得"比猜更差"）；迭代保持相对既有分类 `Δerr ≤ −sandboxImprovement`。理由：证据硬约束（≥3 条后端验证、pairwise 相干的真实经验）已经把关簇质量，而 15% 余量在年轻 store 的 2-3 条验证切片上统计上无意义——它只阻塞了激活。

**B —— 回退簇走同一道证据闸门。** 确定性分组在写回前必须通过**完全相同的** `verifyEvidence` 硬约束。零通过候选的重建不写任何东西，返回 `证据校验未通过：N 个候选簇均未满足证据约束…`，而不是默默复活被驳回的簇。确定性下界保持诚实：不相干的链式组被拒，绝不写回。

**C —— 模板调用请求关闭思维链。** `callJson` 为全部四个结构化调用（SAR 提取、OOD 复核、校准、重构）设置 `reasoningEffort: ReasoningEffortId('off')`。这些是小型 token 预算下的 JSON 提取任务，推理只会饿死答案。主代理循环保留自己的 provider 默认。

**D —— 重构提示词传达证据相干性要求。** `RECONSTRUCT_SYSTEM_PROMPT` 要求证据属于同一效用模式（三个维度各自与簇均值相差不超过 ~3），警告 `energy_cost` 会把表面相似的"成功"拆成不同簇，并把离群/中性/孤立事件路由到噪声池。

**E —— 重构锚定情境-策略配对的重现模式。** 任务框架从"按结果效用相似性聚类"改为"按情境-策略配对的重现模式聚类"：同一行动在不同前提（行动者水平、环境约束、时间压力）下策略不同时拆分为独立簇；情境措辞不同但策略相同则合并；只有稳定且有 ≥3 条支撑实例的模式才拆簇。前提分化因此**随经验累积自动涌现**——不硬编码任何行动者/环境字段；≥3 证据下限就是自然的分化阈值（模式需在训练切片内累积够实例才能自成簇）。

**F —— 情境质心来自证据而非全部成员。** `writeBack` 的 `situationCentroid` 改为由簇的证据经验（模型选定的模式核心）推导，而非全部结果相似成员。结果向量相同的前提分化簇若按结果归属会互相抢全部成员、把质心稀释成混合物，分化会在检索层死掉。

**G —— 有界重构重试。** 重构路由是随机的：一次抽样可能返回 0 个簇或全部不相干证据，下一次却返回可用集合。`runRebuild` 在抽样产出无验证簇时按 `reconstructRetries`（新配置，默认 2）有界重试，使单次坏抽样无法静默阻塞数据本可支撑的重建。确定性回退仍是全部抽样失败后的最终安全网。

**H —— 检索咨询分类体系（结构层自我认知）。** `predict` 在盲扫之外新增 `taxonomyContext`：查询情境对每个簇的情境质心（任意极性）打分，报告 `coverage: 'covered' | 'gap' | 'no-taxonomy'`（低于新配置 `coverageThreshold`，默认 0.3，即为缺口）、命中的簇、以及路由余量（最佳减次佳余弦）。`PredictResult` 携带它，工具输出暴露 `taxonomy_context`，建议文本追加一行：余量过薄（< 0.1）时"命中簇「…」（相似度 X，路由余量 Y，路由置信低）"，缺口时"情境落在分类覆盖缺口（最高相似度 X < 阈值），SAR 无相关经验"。这是管道自我认知的结构层：检索在扫描前就知道 SAR 里有什么，模型也能看到确定性路由何时不可靠并转用 LLM 路由。它把前提误路由失败（新手情境→簇9，余量 0.05）从**静默**变为**可见**。

**I —— 元经验：管道自身的通道。** `Experience` 增加可选 `meta` 标记，用于管道自身观察（检索路由失败等）。元经验样本在校准提示词中标记为 `【元经验-管道自身】`，让模型知道某个 top-K 命中是已记录的失败模式及其对策。

**J —— 检索失败自动 sar 化。** 熟路预测后，若分类路由余量过薄（低于新配置 `retrievalFailureMargin`，默认 0.1）且无相似行动的元经验（余弦 ≥ 0.8 去重），服务自动合成元经验：情境 = 路由歧义观察，行动 = 原始查询行动（使未来查询可检索到它），结果 = 对策（"确定性路由不可靠，应改用 LLM 路由"），效用 (3,4,5)。这正面回答了"检索失败的经验能不能 sar 化"——能，而且是自动的。

**K —— 元经验进入冷环采样。** 采样过滤器纳入非中性效用的元经验（它们没有用户误差信号通道），且 `cap()` 永不截断它们（数量少且已去重，按误差排序的预算截断会把它们排在末尾丢掉）。

**L —— 元经验永远进训练、不进验证。** 它们是学习信号而非留出验证数据：永远加入训练切片，使重构能聚类检索失败模式（LLM 形成 `[exp_55, exp_56, exp_57]` 相干风险簇，maxDist 0.699），也永远不会污染验证回测（其低 gain 效用会被成功簇过度预测）。

## 备选方案

**放宽 `evidenceMaxDistance`（0.85 → 0.95）。** 拒绝：链式组失败于真实的效用几何差异（代价槽反号）；放宽上限会削弱防幻觉锁，而这是聚类应当拆分而非容忍的数据分布缺口。

**收紧 `clusterMergeCosine` 拆链。** 拒绝：质心链式合并在该数据上直到 0.65 仍存在；且 LLM 路由（按效用模式语义分组）才是上限——确定性下界只需要不腐化。

**提高 `maxTokens` 容纳思考。** 拒绝：推理 token 是被丢弃的输出；对结构化提取来说，关闭思维链既正确又免费，加大预算既慢又贵。

**硬编码行动者/环境前提字段。** 拒绝：决策 E 的整个要点就是分化从累积文本模式中涌现；固定前提维度既脆弱又违背"经验累积、SAR 分化"的要求。

## 后果

51 条经验（其中 13 条新手/资深打包推送实例）下，`rebuild_taxonomy('global')` 验收了 taxonomy v4：LLM 锚定了**两个前提分化簇**——簇8（证据 exp_39/40/44/45）"if 用户是初学者且任务涉及git初始化、远程推送或发布流程 then 先讲解原理并演示完整命令，附上检查清单"与簇9（证据 exp_41/42/43/46/47）"if 用户非新手且任务为常规提交推送 then 跳过讲解直接使用最短命令完成"——外加一个环境修复簇，`Δerr = −25%`（迭代门槛）。实时预测确认**建议层分化生效**（新手 →"用简单示例先练手，分步操作"；资深 →"先验证权限和网络，再快速推送"），尽管确定性 `matchSuccessReference` 的情境质心路由不完美（新手情境对簇8 余弦 0.552、对簇9 却是 0.602——前提判别 token 在短中文情境的 384 维词袋余弦中被稀释）。已知限制：确定性情境路由可能选错前提簇；LLM 校准层路由正确。决策 H 让检索现在**主动暴露**这个限制：新手打包查询返回 `taxonomy_context.coverage='covered', similarity=0.602, margin=0.050`，建议文本显式标注 `路由置信低`；陌生查询（写诗）返回 `coverage='gap'` 与"SAR 无相关经验"；首次重建前的 store 返回 `no-taxonomy`。边界提示：环境故障查询余弦 0.291，恰好低于 0.3 的 `coverageThreshold`——该阈值的校准是后续调优点。决策 I-L 让检索失败**自动 sar 化**：新手打包与新手发布预测自动合成了元经验 exp_56/exp_57（另有手工记录的 exp_55），模拟重构抽样形成了相干的 `[exp_55, exp_56, exp_57]` 风险簇——闭环由模拟与单元测试证明；线上写回仍受诚实回测把关（最新留出的低 gain 切片尚未被训练派生簇很好预测，这是设计中的累积动态而非缺陷）。测试：56/56 包测试（元经验采样、元经验检索、校准标记）、host 聚合 typecheck、oxlint 全部通过；决策 A-D 测试保留。
