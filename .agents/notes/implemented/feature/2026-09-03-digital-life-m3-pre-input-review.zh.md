# Agent Note: 数字生命 M3——主会话预输入回顾

Status: implemented

[English](2026-09-03-digital-life-m3-pre-input-review.md) | 中文

## 问题

pre-step 预热交付的是原始记忆：检索到的经验以【认知经验参考】块注入，主模型得自己做综合——一边回答用户，一边读散落的条目、判断相关性、提炼教训。运营者对数字生命 M3 里程碑的要求提出了更强的形态：在主对话回答真实用户输入之前，应当先有一趟回顾——回看过往经验并分析，回到主对话的是分析结果而非原始条目。

## 决策

`cognitive-inject` 现提供可选开启的**预输入回顾**通道（`review.enabled`，默认 false；web profile 已启用）。在回合第一步、会话为根会话、输入有实质内容且会话不在回顾冷却期内时，会生成一个回顾子代理，其提示词携带用户输入、检索并通过评审的经验（至多 `maxHits` 条）与当前情景链头（situational-state 插件挂载时软读取）。子代理的综合分析以一条【过往经验回顾】插件消息反代回主对话，**替换**该步的原始经验块。任何跳过、超时、spawn 失败或空输出都会回退到既有原始注入——回顾是严格的加法升级。

- 子代理走普通 `spawn` provider（默认 `review.provider`）；提示词自带检索材料，因此无需 SAR 包装，机制不依赖编排包装层。
- 递归防护：仅当会话 header 无 `parentSession` 时才运行回顾——回顾子代理自身的会话是子会话，绝不会回顾自己的输入。
- 门控旋钮：`minTextChars`（默认 60——闲聊绝不派生子代理）、`cooldownMs`（默认每会话 120 秒）、`timeoutMs`（默认 45 秒——到期后注入原始块并丢弃迟到的子代理输出）、`maxHits`（默认 3）。
- 注入台账以 `triggerSource: pre-input-review:<gate>` 记录回顾及其 expIds，引用度量与强化循环把它当作任何一次注入处理。

## 验证

`cognitive-inject` 测试（34 绿，6 新）：根会话第一步上回顾综合块替换原始块（断言【过往经验回顾】文本、无【认知经验参考】、`pre-input-review:` 触发来源）；未挂 subagents 接缝时注入原始块（回退）；空回顾输出回退原始；同回合第二步不回顾；子会话（header 设 `parentSession`）绝不回顾；`buildReviewPrompt` 携带输入、链头、expId 与输出要求。web profile 补丁为主对话启用回顾；相关包宿主类型检查干净（宿主残留错误仅剩运营者既有的 WIP spec）。

## 备选方案

- **不用子代理、直接 LLM 综合**：pre-step 内联调用 LLM 路由并注入其综合。否决——回顾应在主上下文之外进行，只把结论跨回主对话；子代理提供运营者要求的全新上下文回顾，且不撑大主窗口。
- **每条消息都回顾**：不论长短，每个用户回合都派生子代理。否决——延迟与成本随闲聊线性增长；实质输入下限与会话冷却让回顾只落在真工作上。
- **保持纯原始预热**：原始块已携带记忆，无需新增。否决——运营者明确要求把经子代理分析过的形态反代回主对话；原始块仍是确定性回退。

## 后果

真实的、有实质内容的主对话输入现在会在模型回答前得到一次有经验依据的回顾：用户看到的是经过显式回看步骤的答案，原始记忆噪音留在主窗口之外。代价：合格回合的第一步会阻塞于一次子代理运行（受 `timeoutMs` 约束；子代理失败时回退保持回合推进），每次回顾在每个冷却窗口内花费一次子代理补全。回顾子代理由 `parentSession` 防护排除回顾自身输入，因此不存在递归回路。
