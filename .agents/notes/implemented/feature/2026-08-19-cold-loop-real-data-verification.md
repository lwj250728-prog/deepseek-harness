# Agent Note: Cold-loop real-data verification — two-regime acceptance, fallback evidence integrity, reasoning-off templates, premise-differentiation emergence, taxonomy-aware retrieval, reference experiences

Status: implemented

English | [中文](2026-08-19-cold-loop-real-data-verification.zh.md)

Supersedes (partially): [2026-08-18-cold-loop-acceptance-first-build-and-deferral.md](2026-08-18-cold-loop-acceptance-first-build-and-deferral.md) — decision A's first-build margin is relaxed from ≥15% to non-worsening; the baseRate-baseline reference and the deferral design stay in force.

## Problem

The first real-data cold loop (35 experiences, 15 sampled, the real `deepseek-official/deepseek-v4-flash` route) never accepted a rebuild. Synthetic tests (identical utility vectors per family) masked three blockers, live premise-differentiation experiments exposed a fourth, and the self-cognition question exposed a fifth:

- **Unreachable first-build margin.** Acceptance required `Δerr ≤ −15%` against the empty-view baseRate baseline. A 2-3 sample validation slice caps any measurable improvement well below 15%: with 2 validation points where only one matches a cluster, the measured ceiling was −6.98%. The first build could never pass, so the store sat at taxonomy version 0 forever.
- **Fallback bypassed evidence verification.** When every model cluster was rejected, `finalCandidates = verified.length > 0 ? verified : fallbackCandidates(groupsWithUtility, byId)` re-introduced the *unverified* deterministic groups — a cluster already rejected by the pairwise-distance check could still be written. Real data demonstrated it: the agglomerative merge (cosine 0.4) chained a high-cost outlier into the success family, producing a group whose pairwise max distance (0.960) exceeded `evidenceMaxDistance` (0.85); the check rejected it, but the fallback path resurrected it.
- **Template calls silently starved.** `deepseek-v4-flash` runs thinking by default. The pipeline's structured calls are budget-constrained (`callJson` maxTokens 500-4096); chain-of-thought consumed the entire budget, yielding `finish: max-tokens` with zero text. Every reconstruct call threw `LLM_MAX_TOKENS`, degraded to the deterministic fallback, and the improved prompt never reached the model — the LLM route (the design's ceiling) was dead on arrival without any error surfacing in the rebuild result.
- **Premise differentiation could not reach the taxonomy.** For the same action (e.g. packaging and pushing to GitHub) under different premises (novice-needing-teaching vs expert-wanting-minimal), the outcome-based clustering and outcome-based member assignment coalesced the experiences regardless of premise: the situation never fed back into clustering or assignment, so `situationCentroid` diluted into a mixture and `matchSuccessReference` could not route by premise.
- **Retrieval did not consult the taxonomy.** Even after the taxonomy existed, retrieval was a blind scan: `retrieveTopK` never asked "does SAR have knowledge here, and in which strategy region?" — so coverage gaps, routing confidence, and the risk of premise mis-routing were invisible to both the pipeline and the model. The self-cognition question ("can SAR know what SAR contains and advise retrieval?") has no mechanism to answer it.

## Decision

**A — two acceptance regimes.** `firstBuild = store.clustersSnapshot().length === 0`. A cold start accepts the first verified cluster set when `Δerr ≤ 0` against the empty-view baseRate baseline (never measured *worse* than guessing); iteration keeps `Δerr ≤ −sandboxImprovement` against the existing taxonomy. Rationale: the evidence hard constraint (≥3 backend-verified, pairwise-coherent experiences) already gates cluster quality, and the 15% margin is statistically meaningless on the 2-3 sample slice a young store can produce — it only blocked activation.

**B — fallback clusters pass the same evidence gate.** The deterministic groups are re-verified through the identical `verifyEvidence` hard constraint before any write-back. A rebuild with zero verified candidates writes nothing and reports `证据校验未通过：N 个候选簇均未满足证据约束…` instead of silently resurrecting rejected clusters.

**C — template calls request reasoning off.** `callJson` sets `reasoningEffort: ReasoningEffortId('off')` for all four structured calls (SAR extraction, OOD review, calibration, reconstruction). These are JSON extraction tasks on small token budgets; reasoning only starves the answer. The main agent loop keeps its own provider default.

**D — reconstruction prompt states the coherence requirement.** `RECONSTRUCT_SYSTEM_PROMPT` requires evidence to be one utility pattern (each of the three dimensions within ~3 of the cluster mean), warns that `energy_cost` splits superficially-similar successes into distinct clusters, and routes outliers/neutrals/singletons to the noise pool.

**E — reconstruction anchors on situation–strategy recurrence.** The task framing changed from "cluster by outcome-utility similarity" to "cluster by recurring situation–strategy pairings": the same action under different premises (actor level, environment constraints, time pressure) with different strategies splits into separate clusters; situation-wording differences with the same strategy merge; only stable patterns with ≥3 supporting instances split. Premise differentiation thus **emerges from accumulation** — no actor/environment fields are hardcoded; the ≥3-evidence floor is the natural emergence threshold (a pattern needs enough in-sample instances to form its own cluster).

**F — situation centroids come from evidence, not all members.** `writeBack` derives `situationCentroid` from the cluster's evidence experiences (the model-chosen core of the pattern) rather than every outcome-similar member. With outcome-identical premise-differentiated clusters, outcome-based membership would claim both patterns and dilute the centroid into a mixture, killing the differentiation at retrieval.

**G — bounded reconstruct retries.** The reconstruct route is stochastic: one draw may return zero clusters or all-incoherent evidence while the next returns a usable set. `runRebuild` retries up to `reconstructRetries` extra draws (new config, default 2) whenever a draw yields nothing verified, so a single bad draw cannot silently block a rebuild the data supports. The deterministic fallback remains the final safety net when every draw fails.

**H — retrieval consults the taxonomy (structural self-knowledge).** `predict` now computes a `taxonomyContext` in addition to the blind scan: the query situation is scored against every cluster's situation centroid (any polarity), reporting `coverage: 'covered' | 'gap' | 'no-taxonomy'` (below the new `coverageThreshold` config, default 0.3, it is a gap), the routed cluster, and the routing margin (best-minus-second-best cosine). The `PredictResult` carries it, the tool output exposes `taxonomy_context`, and the advice appends a compact line: "命中簇「…」（相似度 X，路由余量 Y，路由置信低）" when the margin is thin (< 0.1), or "情境落在分类覆盖缺口（最高相似度 X < 阈值），SAR 无相关经验". This is the structural layer of the pipeline's self-knowledge: retrieval knows what SAR contains before it scans, and the model can see when the deterministic routing is unreliable and defer to LLM routing. It makes the premise mis-routing failure (novice situation → 簇9 at margin 0.05) *visible* instead of silent.

**I — meta experiences: a pipeline-own channel.** `Experience` gains an optional `meta` flag for pipeline-own observations (retrieval-routing failures, etc.). Meta samples are marked `【元经验-管道自身】` in the calibration prompt, so the model sees when a top-K hit is a recorded failure pattern with its countermeasure.

**J — retrieval failures are SAR-ized automatically.** After a known-path prediction, if the taxonomy routed with a thin margin (below the new `retrievalFailureMargin` config, default 0.1) and no meta experience with a similar action exists (dedupe at cosine ≥ 0.8), the service synthesizes a meta experience: situation = the routing-ambiguity observation, action = the original query action (so it is retrievable by future queries), outcome = the countermeasure ("确定性路由不可靠，应改用 LLM 路由"), utility (3,4,5). This answers "can retrieval failures be SAR-ized?" with yes — automatically.

**K — meta experiences join the cold-loop sample.** The sampling filter admits meta experiences with non-neutral utility (they carry no user-error signal), and `cap()` never truncates them (they are few and deduplicated, so the error-first budget sort would otherwise drop them).

**L — meta experiences always train, never validation.** They are learning signal, not held-out user data: they always join the train slice so the reconstruct can cluster retrieval-failure patterns (the LLM forms `[exp_55, exp_56, exp_57]` as a coherent risk cluster, maxDist 0.699), and they never skew the validation backtest (their low-gain utilities would be over-predicted by success clusters).

**M — reference experiences: the second cold-start source (scheme 3).** `reference_experience` generalizes *from what already happened* instead of guessing *what might happen* (that is `simulate_experience`): it retrieves the top-`referenceTopK` (default 5) most similar real experiences by dual-axis max cosine (action and situation), asks the LLM route (template 6 "经验归纳官") to extract their **shared pattern** — the typical situation/action/outcome/utility of "这类情境通常如何解决" — and writes the generalization as a retrieval-only simulated candidate (`simulated: true`, `verification: 'unverified'`, `evidenceScore: 0`) that the same evidence-replacement lifecycle verifies against real feedback. Two deterministic guards prevent fabrication: anchors must be real history (`simulated` experiences never anchor), and a hit needs dual-axis similarity ≥ `referenceMinSimilarity` (default 0.3); when no anchor survives, the derivation rejects **without an LLM call** (no commonalities → nothing to generalize). The no-route fallback also rejects deterministically. This is the second of the two cold-start sources the design specifies (主动探索 is the remaining one, with its scratchpad passive form already live).

**N — multi-channel retrieval: fusion, feedback-learned weights, and LLM refine (V3.1).** The single action-cosine retrieval channel is replaced by a **four-channel fusion** mirroring human recall: semantic (action cosine, via a pluggable `SemanticScorer` seam — hash-bag default, real embeddings slot in behind the same interface), situational (query-situation vs experience-situation cosine; premise differentiation lives here), symptom (`symptomOverlap` failure-signature substring recall), and outcome (negative-polarity priority when the query itself carries a failure marker). `score = Σ w_c·s_c` with per-channel weights persisted in `channel_weights.json` and **learned from feedback** (第一性原理 |calibrated−observed|): at predict time the fused top-1's per-channel contributions (w_c·s_c) are stored on the prediction; at feedback, the dominant channel is rewarded on small error (target 1.6) and penalized on large error (target 0.5), EWMA-clamped to [0.2, 3] (`channelLearningRate` step, `channelErrorThreshold` divider). OOD detection and calibration keep the semantic cosine (threshold semantics unchanged); fusion only decides ranking and the sample set. **Low-confidence deterministic routing no longer just flags**: when the taxonomy margin is thin or OOD is flat-top, the template-7 "检索精排官" reads the fused candidates and drops genuinely inapplicable top hits (bounded by `refineMaxDrops`, default 2; advice marks it `检索复核`), so "语义相似 ≠ 可迁移" gets an LLM arbiter instead of blind trust. The design rationale is documented in TR §3.7: semantic similarity is neither necessary nor sufficient for experience transferability — only real feedback can adjudicate it, which is why the similarity operator itself is now learned rather than a fixed proxy.

## Alternatives considered

**Relax `evidenceMaxDistance` (0.85 → 0.95).** Rejected: the chained group fails on a genuine utility-geometry difference (cost-slot anti-alignment); loosening the cap weakens the anti-hallucination lock for a data-distribution gap that clustering should split instead.

**Tighten `clusterMergeCosine` to split the chain.** Rejected: centroid-linkage chaining persists up to 0.65 on this data; and the LLM route (which reasons about utility patterns semantically) is the ceiling — the deterministic floor only needs to not corrupt.

**Raise `maxTokens` so thinking fits.** Rejected: reasoning tokens are discarded output; reasoning-off is both correct and free for structured extraction.

**Hardcode actor/environment premise fields.** Rejected: the whole point of decision E is that differentiation emerges from accumulated text patterns; a fixed premise dimension would be brittle and contradict the "experience accumulates, SAR differentiates" requirement.

## Consequences

With 51 accumulated experiences (13 of them novice/expert packaging-push instances), `rebuild_taxonomy('global')` accepted taxonomy v4: the LLM anchored **two premise-differentiated clusters** — 簇8 (evidence exp_39/40/44/45) "if 用户是初学者且任务涉及git初始化、远程推送或发布流程 then 先讲解原理并演示完整命令，附上检查清单" and 簇9 (evidence exp_41/42/43/46/47) "if 用户非新手且任务为常规提交推送 then 跳过讲解直接使用最短命令完成" — plus an environment-repair cluster, at `Δerr = −25%` (iteration bar). Live predictions confirm the **advice layer differentiates** (novice → "用简单示例先练手，分步操作"; expert → "先验证权限和网络，再快速推送") even though the deterministic `matchSuccessReference` situation-centroid routing is imperfect (the novice situation scored 0.552 to 簇8 but 0.602 to 簇9 — premise-discriminating tokens are diluted in the 384-dim bag-of-words cosine of short Chinese situations). Known limitation: deterministic situation routing may pick the wrong premise cluster; the LLM calibration layer routes correctly. With decision H, the retrieval now *surfaces* this limitation: the novice-packaging query returns `taxonomy_context.coverage='covered', similarity=0.602, margin=0.050` with the advice explicitly flagging `路由置信低`. A foreign query (poetry) returns `coverage='gap'` with "SAR 无相关经验", and a pre-first-rebuild store returns `no-taxonomy`. Boundary note: the environment-failure query scored 0.291 — just under the 0.3 `coverageThreshold` — so `coverageThreshold` calibration is a live tuning concern. With decisions I-L, retrieval failures are SAR-ized automatically: the novice-packaging and novice-publishing predictions synthesized meta experiences exp_56/exp_57 (plus manually-recorded exp_55), and a simulated reconstruct draw formed a coherent `[exp_55, exp_56, exp_57]` risk cluster — the closed loop is proven by simulation and unit tests; the live write-back is gated by the honest backtest (the newest held-out low-gain slice is not yet predicted well by train-derived clusters, which is the designed accumulation dynamic, not a defect). With decision M, `reference_experience` registers as the seventh model tool: the template-6 LLM route extracts shared patterns from similar history and writes them under the simulated/unverified lifecycle, with deterministic rejection on empty anchor sets (unit-tested: derived reference written as simulated/unverified with evidenceScore 0; empty-anchor and no-route paths return null without an LLM call; simulated experiences and dissimilar hits never anchor). With decision N, retrieval is a four-channel fusion with feedback-learned weights and an LLM refine pass. Unit-tested: the situational channel flips the ranking when the situation matches (semantic-only ranking disagrees), the symptom+outcome channels recall the failure lesson for a failure-flagged query, channel weights move on feedback (reward small error toward 1.6, penalize large toward 0.5, clamped [0.2, 3]) and round-trip through `channel_weights.json` (hostile values clamped on load), the template-7 refine drops an inapplicable top hit (the bound experience switches to the runner-up, advice marks `检索复核`), and the pluggable `SemanticScorer` seam accepts an injected scorer. The full hot loop keeps its behavior with the scripted adapter (refine-keep response inserted before the OOD review). Tests: 72/72 package tests, host aggregate typecheck, and oxlint pass; decisions A-D tests remain.
