# Agent Note：症状优先的 SAR 提取与召回

Status: implemented

[English](2026-08-18-symptom-first-sar-extraction-and-recall.md) | 中文

## 问题

多层注入设计（见 [多层 SAR 经验注入](2026-08-18-multi-layer-sar-experience-injection.md)）修好了 SAR 记忆在*何处*与*何时*召回，却没有修*存储的情境是否携带召回线索*。bug 经验的情境被存成"深夜出现了一个会死循环的浮点 bug"——修复语境，而非失败签名。后来的任务"修复测试挂起问题"与原始 bug 共享症状"挂起"，却不共享修复措辞；对真实经验实测，其双轴余弦为 0.147–0.236，低于一切阈值。检索轴是对的；轴另一端的数据不对。

## 决策

**SAR 提取在两条路径上都症状优先。** `SAR_SYSTEM_PROMPT` 的情境规则现在要求包含可观测失败症状——错误文本、挂起、编译失败、超时、exit code——并声明症状是未来召回的关键线索（"测试脚本突然无限挂起"而非"测试出了问题"）。确定性 `sarFallback` 与之对应：任何携带共享 `SYMPTOM_MARKERS` 表中标记的句子都被融合进情境，无路由的流水线存储与 LLM 路径相同的签名。

**召回增加精确子串症状通道。** `vectorizer.ts` 的 `symptomOverlap(query, text)` 返回查询的症状标记在经验文本中出现的比例。三个检索点——orchestrator `retrieve()`、`dsh-cognitive-inject` 预热、热环——统一以 `max(行动余弦, 情境余弦, symptomOverlap)` 打分。哈希词袋向量会把短症状查询对长情境稀释；精确子串通道是扛住稀释的补集。

## 备选方案

**症状存入专用字段。** 否决：为多一条轴改动 SAR 三元组的持久化格式与所有消费方；把症状融合进情境，向量通道与子串通道都能从已存数据中取用。

**症状融合后仅靠余弦轴。** 否决：实证显示"修复测试挂起问题"对融合后情境仍只有 0.233——短查询在哈希向量中被稀释。只有精确子串通道能跨过阈值。

**用学习型嵌入做症状匹配。** 推迟：这是流水线既有的真实嵌入 deferred work；子串通道是今天就能用的确定性步骤。

## 后果

bug 经验现在把失败签名存进情境，并能在每个召回点（含短症状查询）通过精确子串通道按签名被检索。`SYMPTOM_MARKERS` 被兜底提取与召回打分共享，写数据的词汇与读数据的词汇一致。保留的已知限制：标记表是固定启发式（无学习型同义），查询的症状若在任何存储经验中都不以原词出现，仍会漏检。
