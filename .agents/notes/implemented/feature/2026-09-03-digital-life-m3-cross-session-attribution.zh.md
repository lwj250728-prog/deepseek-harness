# Agent Note: 数字生命 M3——跨会话状态归属如实表述

Status: implemented

[English](2026-09-03-digital-life-m3-cross-session-attribution.md) | 中文

## 问题

注入的情景上下文前言总是声称读取会话拥有该已提交状态：`【情景状态参考】当前会话最近提交的情景状态…`。链跨会话共享——新对话通过链头继承生命线索——因此当会话 B 读取会话 A 提交的链头时，模型被告知了一个关于归属的谎言。跨会话续接（数字生命身份里程碑）依赖读者知道自己在接的是谁的状态。

## 决策

`renderSituationalContext` 增加可选 reader 会话 id 参数；pre-step 监听器传入读取代理的会话。当读者不同于链头的提交会话时，前言点名真实属主并附加一条跨会话说明：

- 同会话或读者中性的渲染保持旧文案 `当前会话最近提交…` 不变；
- 不同读者渲染 `会话 <属主> 最近提交…`，并附【跨会话】说明：该状态由另一会话提交、可以继续推进，且可用 `situational_state_commit` 提交读者自己的新状态。

## 验证

`situational-state` 测试（32 绿，4 新）：不同读者渲染真实属主并带跨会话说明；属主读者保持同会话文案；读者中性渲染保持旧文案；全新会话的首个 pre-step 以真实属主归属注入链头。包类型检查通过；web profile 下次重启加载该改动。

## 备选方案

- **保留假的"当前会话"文案**：零改动零成本。否决——整个跨会话身份设计建立在读者知道自己看到的是谁的状态之上；首次注入就说谎会毒化续接。
- **强制每个跨会话读者延续生命**：附加命令式续接指令。否决——指定是标记而非强制（RFC 的备选方案立场）；该说明只是告知，侧会话可自由忽略。

## 后果

读取生命线索的新会话现在看到诚实的交接：这是谁的状态、它跨了会话、提交自己的状态会推进链。同会话与读者中性的渲染与之前逐字节一致，既有契约与测试保持成立。
