# Agent Note：回合经验气泡——让管线的学习可见

Status: implemented

[English](2026-08-19-turn-cognition-bubble.md) | 中文

## 问题

认知管线在每个完成的回合都在积累、结算、学习，但这些活动在对话中不可见：用户看到的是答案，不是学习。用户提议让它们可见——"像每次进行代码处理那样，在会话结束的底部增加积累的经验气泡"——在对话末尾显示本回合实际教会了管线什么。

## 决策

两半，一条数据路径。

**数据（cognitive-pipeline）。** `summarizeTurn(sessionId, episode)` 聚合一个完成回合的认知活动：结算本回合的注入引用、在 `autoAccumulate` 开启时沉淀回合、并统计自上次 summarize 调用以来该会话已解析的预测数（per-session 计数器，跨会话准确）。它返回 `TurnCognitionSummary`，管线的 `turn/end` 监听（现无条件注册，不再受 `autoAccumulate` 门控）在回合产生活动时把它作为 `cognition/turn-summary` 会话事件追加——纯 UI、非 surface、绝不进入模型请求；安静回合不追加任何事件。turn 结束的引用结算从 `cognitive-inject` 移入 `summarizeTurn`，单一所有者聚合回合活动，消除跨插件竞态；自反中断的延迟补结算（pre-step）保留在注入插件。持久化目录已重新生成，新事件类型成为已知词汇。

**展示（ui-cognition）。** `cognition-summary` 会话节点匹配该事件，在聊天流回合末尾渲染一个可折叠气泡：一行计数（新经验 · 引用 cited/settled · 已解析预测），展开显示经验 id 与主题。节点用结构性窄化读取宿主事件（客户端不声明宿主的会话词汇），并扩展 `ChatNodeDataMap` 使渲染器成为类型安全的 keyed 聊天节点。

## 备选方案

**仅从客户端回合事件渲染气泡。** 否决：引用与经验事实在管线存储里，不在会话事件流中；聚合必须由宿主提供。

**在注入插件结算引用并由此发布气泡。** 否决：摘要还需要沉淀结果（在管线里）；两个所有者会在同一结算上竞态。

**每个回合都显示气泡，安静时为空。** 按用户选择否决：只有实际产生认知活动的回合才渲染，安静回合不打断。

## 后果

- 学习回路现在可见：用户看到每个回合沉淀了什么（新经验、兑现的引用、已解析的预测），并能检查确切的经验 id 与主题。
- turn 结束的引用结算单一所有，消除此前隐含存在的跨插件顺序隐患。
- 成本：一个宿主事件类型（重新生成的目录）、一个带 per-session 计数器的服务方法、一个客户端会话节点 + 渲染器 + locale + CSS，及其测试（宿主 + jsdom 组件 + GUI 套件全绿：3788 个测试）。
- 气泡只在管线有东西可说时出现——安静回合保持安静，符合"有活动才显示"的选择。
