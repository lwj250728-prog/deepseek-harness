# dsh-web-gateway — 有限对象访问 DSH Web 的鉴权网关

把"谁能访问 DSH Web（本机 `127.0.0.1:3080`）"收窄为一份**白名单**。不在名单里的请求一律 401。
零依赖（仅 `node:http`），HTTP 与 WebSocket(Upgrade) 都转发，支持浏览器 GUI 的实时通道。

```
远程对象 ──► 网关(4080, 校验 X-Access-Token) ──► DSH Web(127.0.0.1:3080)
             非白名单请求 → 401，日志留痕
```

## 快速开始

```sh
# 1. 生成白名单 token（给每个"有限对象"一个，别共用）
openssl rand -hex 24

# 2. 编辑 tokens.json，把 token 映射到对象名
#    { "<token>": "alice 的手机", "<token>": "bob 的平板" }

# 3. 启动网关（先确认 DSH Web 已在 127.0.0.1:3080 运行）
node D:\DeepSeek-Harness\data\plugins\dsh-web-gateway\gateway.mjs
```

对象访问方式（二选一）：

| 方式 | 示例 |
|---|---|
| 请求头（推荐，不进地址栏历史） | 浏览器插件/客户端加 `X-Access-Token: <token>` |
| 查询参数（手机浏览器最省事） | `http://<地址>:4080/?token=<token>`（首次进入后页面内请求会自动带上？不会——需脚本注入。**简单可靠做法见下**） |

> 查询参数版有个坑：DSH Web 是单页应用，token 只在首页 URL 上，页面内的 fetch 不会自动带。
> **最省事的手机方案**：本地把 token 填进地址 `http://<地址>:4080/?token=xxx` 打开后，
> 再手动在浏览器控制台执行 `fetch('/api/...')` 类请求时会丢 token——因此**优先用请求头方案**：
> 手机端可用支持自定义头的浏览器扩展（如 Kiwi Browser + Header Editor），或走 SSH 隧道后在
> 电脑/手机本地再放一个"带 token 的简单入口页"。演示级取舍，README 诚实说明。

## 部署与安全（重要）

| 场景 | GATEWAY_HOST | 说明 |
|---|---|---|
| 仅本机 | 不设（默认 `127.0.0.1`） | 最安全，无网络暴露 |
| SSH 隧道 | 不设 | 手机 `ssh -L 4080:127.0.0.1:4080 用户名@电脑IP`，再访问 `127.0.0.1:4080/?token=…`；全程加密、零暴露 |
| 虚拟局域网 | 设 Tailscale IP | `set GATEWAY_HOST=100.64.x.x && node gateway.mjs`，配 Tailscale ACL 只放行对象设备 |
| 直接远程 | 显式 `0.0.0.0` | **必须**配防火墙只放行信任来源 IP，且强烈建议前置 HTTPS 反代；这是最大的暴露面，非必要不用 |

**规则**：
1. token 用 `openssl rand -hex 24`（≥32 字符）生成，**每个对象一个**，泄漏即单独轮换。
2. 网关转发是 HTTP 明文——**请走 SSH 隧道 / Tailscale**；直接公网暴露时必须加 HTTPS。
3. 日志即审计：每行含时间、对象名、方法、路径、状态码，能回答"谁在什么时候访问了什么"。
4. 不要用 `GATEWAY_HOST=0.0.0.0` + 路由器端口转发 + 弱 token 的组合。

## 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `GATEWAY_HOST` | `127.0.0.1` | 网关监听地址（远程对象可达才改，见上表） |
| `GATEWAY_PORT` | `4080` | 网关端口 |
| `DSH_WEB_TARGET` | `http://127.0.0.1:3080` | 转发目标（DSH Web） |
| `GATEWAY_TOKENS` | 同目录 `tokens.json` | 白名单文件路径 |

## 局限（演示级，如实说明）

- 无 HTTPS 终结、无速率限制、无失败重试——面向"本地/隧道/虚拟网"的可信链路。
- token 放查询参数会进入浏览器历史与网关日志（日志只记对象名不记 token，但浏览器侧仍建议用请求头）。
- 未做会话级授权（DSH Web 自身若有登录，网关不参与）。
- 未与 DSH 进程集成（独立进程更安全：DSH 本体仍只绑回环，网关故障不影响 DSH）。
