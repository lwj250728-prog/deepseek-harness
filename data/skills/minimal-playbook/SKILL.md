# 极简模式自我优化手册（minimal-playbook）

> 来源：DSH 检出源码级解剖（`apps/cli/config/agent-presets/minimal/agent.cordis.yml` 62 行 vs `standard` 251 行）。
> 极简模式本质 = **一句 persona（complete:true）+ 2 个工具（persistent-bash、str_replace_editor）+ 无压缩 + 无沙箱 + 无运行时上下文**。
> 省的是每轮请求的固定开销（提示词段 + 工具 schema，约 4K–10K token/轮）。

## 触发条件（满足其一即加载本技能）

1. 任务是简单/确定性的（查一个事实、改一处文本、跑一个命令）
2. 会话预期很短（≤5 轮）或高频重复
3. 需要主动控制 token 开销
4. 执行层故障（pwsh 不可用、写路径被阻断）——切纯工具能力路线
5. 用户明确要求"极简/省 token/快速"

## 行动纪律

### 1. 工具面最小化（"双工具"心态）

- 读文件用 `read`（带 limit/offset）；查文件用 `glob`/`grep`。
- `pwsh` 只在真正需要执行/测速/构建时用；简单事实查询先走文件工具。
- 一次调用解决一件事，避免连环小调用。

### 2. 输出节流（对齐 16K 上限）

- 读大文件分段（limit/offset），不整读。
- 让工具输出保持小：grep 取匹配行，不 cat 大文件。
- 输出"截断到尾部"是特性：先看尾，再决定是否补读。

### 3. 状态外置（模拟持久 shell）

- 跨调用状态写进工作区/暂存文件，不指望 shell 变量（pwsh 每轮是新进程）。
- 多步操作合成一条命令，减少往返。

### 4. 前缀稳定（吃 KV cache）

- 系统提示词前缀保持稳定，不反复改格式。
- 长任务拆短会话——极简模式无压缩，超长上下文无兜底。

### 5. 提示词体积：persona 即提示词

- 认知框架摘要保持一句话级；只写经校验的分类摘要。

### 6. 安全边界的自知

- 极简模式的"无沙箱"换效率；本会话保持写路径纪律（工作区/临时区）。
- 执行层故障（EPERM/pwsh 挂掉）：不反复重试，切纯工具能力继续，如实告知。

### 7. 认知补齐：极简缺什么，管道补什么

- 结论性经验 → `remember_experience` 入 SAR 记忆。
- 不确定行动 → `predict_outcome` 出校准概率，事后 `report_outcome` 闭环。
- 样本足够（≥3 证据/簇）→ `rebuild_taxonomy` 让分类体系自我重构。

## 反模式（不要做）

- 简单任务也上全套工具（subagent/workflow/web）——固定开销翻几倍。
- 反复重试被基础设施拒绝的操作（写路径 EPERM、pwsh 挂）。
- 把临时结论写进系统提示词。
- 在极简会话里跑超长任务不拆分。
